BUILD FROM THE SOURCE ARCHIVE

The add-on is written in TypeScript and bundled by WXT (Vite), so the submitted code is generated. The source archive is the repository at the released commit. No file is minified by hand and nothing is downloaded at run time.

Requirements: Node.js 24 and pnpm 12.14.0 (the version in package.json's packageManager field). The release is built on Ubuntu (GitHub Actions); the build also runs on macOS.

  pnpm install --frozen-lockfile
  pnpm zip:firefox

This writes the unpacked add-on to .output/firefox-mv3/ and the package to .output/ntfy-desk-<version>-firefox.zip. pnpm-lock.yaml pins every dependency; pnpm-workspace.yaml applies one patch from patches/ to a development tool (the add-on linter's deepmerge), which is not part of the add-on.

TESTING

ntfy Desk is a client for ntfy (https://ntfy.sh), a separate open-source project. It needs a ntfy server; it has no account or service of its own. The public server https://ntfy.sh works without an account:

1. Click the toolbar icon, open Settings (gear), tab Server: enter https://ntfy.sh as the server URL and choose "Save server settings".
2. Tab Topics: add a topic with a name that is hard to guess, for example ntfy-desk-review-<random letters>. Topics on ntfy.sh are public: anyone who knows the name can read it, so send test content only.
3. Send a notification from the Send form. It arrives in the inbox and as a desktop notification.
4. To publish from outside the add-on: curl -d "hello" https://ntfy.sh/<your topic>
5. Right-click a page, a selection, a link or an image for the context-menu sends.

No credentials are needed for ntfy.sh. Access tokens, usernames and passwords are only for servers with access control; a self-hosted server can be started with: docker run -p 8080:80 binwiederhier/ntfy serve

PERMISSIONS

- storage, unlimitedStorage: settings, the inbox (received messages, kept on the device) and the queue of attachments waiting to be sent.
- notifications: desktop notifications for received messages.
- alarms: a one-minute alarm to reconnect and fetch missed messages.
- contextMenus, activeTab: the right-click sends and "Fill in the current tab" read the active tab's title and URL after a user action.
- scripting: one call (utils/context-menu.ts, getLinkText) that reads the text of the link the user right-clicked. The function is part of the package.
- tabs (optional): requested by "Use tab" in the add-on's own tab, to read the title and URL of the page the user was on.
- <all_urls> (optional host permission): never requested as a whole. The add-on requests one origin at a time, after a click: the user's ntfy server when credentials or deletion sync are configured (the Authorization header needs host access), and the site of an image sent from the context menu.

DATA

data_collection_permissions declares authenticationInfo, personalCommunications, browsingActivity and websiteContent because this data is sent to the ntfy server the user configured: credentials in the Authorization header, the notifications themselves, and a page's title, URL, selected text or image when the user sends it. Nothing is sent to the developer; there is no analytics or other remote service. PRIVACY.md in the source archive is the privacy policy.

Remote content is treated as data: messages are validated (utils/ntfy.ts, parseMessage) and rendered with textContent; Markdown is built as DOM nodes (utils/markdown.ts). ARCHITECTURE.md, "Security model", describes this.
