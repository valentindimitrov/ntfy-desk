NTFY DESK: NOTES FOR REVIEWERS (Firefox Add-ons)
Paste the text below the line into "Notes to Reviewer" (AMO accepts at most 3,000 characters; a unit test checks it). Upload ntfy-desk-<version>-sources.zip as the source code.
----------------------------------------------------------------------

BUILD

TypeScript bundled by WXT (Vite): the submitted code is generated; nothing is minified by hand. The source archive holds the repository at the release commit, without the website (website/), the store images, hidden folders (.github/) and test output. All code ships in the package. At run time it downloads data only: messages and image previews from the user's ntfy server, and an image the user sends from the context menu.

Node.js 24 and pnpm 12.14.0 (packageManager in package.json):

  pnpm install --frozen-lockfile
  pnpm zip:firefox

Output: .output/firefox-mv3/ and .output/ntfy-desk-<version>-firefox.zip. The patch in patches/ applies to a development tool only (the linter's deepmerge).

TESTING

No account is needed: https://ntfy.sh is a free public ntfy server.

1. Toolbar icon > Settings (gear) > Server: enter https://ntfy.sh and choose "Save server settings".
2. Topics: add a hard-to-guess topic, e.g. ntfy-desk-review-<random letters>. ntfy.sh topics are public: send test content only.
3. Send from the Send form: it arrives in the inbox and as a desktop notification. From outside: curl -d "hello" https://ntfy.sh/<topic>
4. Right-click a page, a selection, a link or an image to send it.

PERMISSIONS

- storage, unlimitedStorage: settings, the inbox and queued attachments, on the device.
- notifications: desktop notifications for received messages.
- alarms: reconnect and catch up every minute.
- contextMenus, activeTab: the right-click sends and "Fill in the current tab" read the active tab's title and URL after a user action.
- scripting: one call (utils/context-menu.ts, getLinkText) reads the text of the right-clicked link.
- tabs (optional): requested by "Use tab" in the add-on's own tab, to read the title and URL of the web page used last.
- <all_urls> (optional): never requested as a whole. Only the user's ntfy server and its fallback, together (from "Allow access to this server", for credentials or deletion sync), and the site of an image sent from the context menu.

DATA

authenticationInfo, personalCommunications, browsingActivity and websiteContent are declared because they go to the user's own ntfy server: credentials in the Authorization header, the notifications, and a page's title, URL, selected text or image when the user sends it. Nothing goes to the developer; there is no analytics. Server data is validated (utils/ntfy.ts, parseMessage) and rendered with textContent. Privacy policy: PRIVACY.md.
